# 跨模块自主机制研发

本次扩展对应用户要求“达到跨模块自主扩展能力”。目标不变：固定模型、物理资源、负载和评分口径，完整完成请求，改善满足延迟目标的吞吐。开发方向由瓶颈证据决定，不再用既有优化名称或单个模块白名单限定。

本文件给出行为契约与验收依据；启动和提交命令见 [SEARCH.md](SEARCH.md)，运行权限以冻结的 `candidate.py`、控制器和检查器为准。源码依据为 `23ae21f81e9431f803c9468dd6c78f5d98d24d7b` 及当前工作区；实际实验身份使用 manifest 中的完整源码和输入哈希，不能仅用 Git HEAD。

新增机制必须说明状态 owner、创建/更新/释放事件、消费该状态的决策、引入的依赖，以及计算/通信/容量成本在哪条原生路径计入。只增加报表字段而不改变消费决策不算实现机制。

## 提交与晋级契约

结构化研究计划应包含：瓶颈证据、假设、预期改变、替代解释、受影响不变量、新增测试、关闭方式、反例和停止条件。证据引用必须落到宿主已封存的基线或评测身份；一个可随时修改的笔记路径不能独立充当基线证据。检查命令由可信 runner 生成，不接受 agent 提交任意宿主命令。

实际变更决定检查集，agent 的影响声明只补充解释。冻结外部测试和宿主注入的公共资源 fixture 不能删除或修改；Rust 源文件内的单元测试可随实现调整，只作为补充证据。新模块和新测试可以自主添加。检查包含基线已有语义及新机制的区别性样例；“测试退出 0”不等于检查了足够的性质。

区分实验执行、待审清单与正确性结论。`review-candidates.json` 汇总相同候选的全案例覆盖、匹配对照和干净重放，始终保留 `EXPLORATORY`。其中 `comparison_reference_reproduced` 只说明引用的 control 在该案例复现了参考且策略匹配；尚未证明后来 candidate 的同源关闭路径等价，不能据此签发正确性晋级。条件不足时记录缺口，不将其当作已证明的机制收益。不同策略独立优化的结果不能直接解释为机制与策略的纯交互收益。

保持 A 原始机制+参考策略、B 原始机制+优化策略、C 新机制+参考策略、D 新机制+优化策略、E 消融。关闭对照用于验证原语义回归，消融用于区分收益来源，两者不能自动互相替代。

## 验证依据与边界

| 要求 | 推导 → 预期观测 → 排除的捷径 |
|---|---|
| CM1 | 用户允许跨模块实现 → 包含 engine/resources/新模块的合法差异通过封存 → 排除仅改文档、旧路径限制仍生效 |
| CM2 | 吞吐比较要求同一工作量与成本 → 事实/工具变化被拒绝、完整请求逐条校验 → 排除删工作、改价格和改评分 |
| CM3 | agent 不能自证新机制正确 → 宿主选冻结检查且保护已有测试 → 排除删除失败用例、少报影响范围和仅靠自写测试 |
| CM4 | 收益须相对可复现反事实 → 证据身份、案例、关闭回归和重放逐项核对 → 排除跨负载借用结果或用路径字符串冒充证据 |
| CM5 | 用户尚未授权本轮运行搜索 → 只使用临时文件及 mock 子进程验证控制流 → 排除把启动条件通过写成真实机制效果通过 |
| CM6 | 文档是研究启发而非当前实测 → 保留 PDF SHA256、完整 33 页及页码映射 → 排除只读摘要、套用外部曲线或将建议变成新白名单 |

本轮检查对象是自主研发系统，不是某个未来机制的性能。真实构建、资源/KV/引擎回归、完整案例和重放由后续启动执行；本次未执行。具体本轮测试结果应以最终交付说明和测试输出为准。

严格私有路由 oracle 和不可见 holdout 尚未实现。冻结函数、独立检查、完整请求和重放都不能证明任意新机制的数学正确性，尤其不能仅从输出 token 时间反推内部工作守恒。缺少内部信号时，应增加有界原生观察或区别性 fixture，不能伪造 trace。结果继续标明探索与可复现范围，不自动宣称 `VERIFIED`、真实 GPU 改善或一般性正确。
